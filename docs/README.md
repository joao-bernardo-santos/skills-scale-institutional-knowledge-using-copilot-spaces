# OctoAcme Project Management Documentation

Welcome to the OctoAcme Project Management Documentation hub. This collection of guides provides comprehensive guidance for managing projects, from initiation through retrospectives, ensuring consistent, repeatable execution across all OctoAcme initiatives.

## Overview

OctoAcme uses a structured, iterative project management approach focused on delivering customer value through clear ownership, data-informed decisions, and psychological safety. This documentation provides guidance across the entire project lifecycle, from the initial spark of an idea to post-release retrospectives.

### Core Principles

- **Customer-first**: Prioritize customer value and usability in all decisions
- **Iterative delivery**: Deliver small, testable increments that generate early feedback
- **Clear ownership**: Each project has named Project Manager and Product Lead responsible for success
- **Data-informed decisions**: Measure impact and iterate based on evidence rather than assumptions
- **Psychological safety**: Encourage feedback, questions, and learning across the team

### Project Lifecycle

OctoAcme projects follow a consistent five-phase lifecycle:

1. **Initiation** — Validate the problem statement, identify stakeholders, and confirm business alignment before committing resources
2. **Planning** — Break work into shippable increments, identify dependencies, and establish clear success criteria
3. **Execution** — Build, test, review, and iterate with daily standup rhythms and transparent progress tracking
4. **Release** — Deploy with confidence through standardized checklists, smoke tests, and rollback plans
5. **Retrospective** — Capture learnings and convert insights into actionable improvements for future projects

## Key Concepts at a Glance

### Core Roles

| Role | Responsibility |
|------|-----------------|
| **Project Manager (PM)** | Coordinates delivery, manages schedules, escalates risks and blockers, maintains stakeholder communication |
| **Product Manager (PdM)** | Defines outcomes and success metrics, prioritizes backlog, measures impact and validates solutions |
| **Developer** | Implements features, writes tests, participates in design reviews, identifies technical risks |
| **QA/Testing** | Validates quality standards, tests acceptance criteria, ensures compliance with Definition of Done |

### Key Artifacts

Projects maintain a consistent set of artifacts to ensure clarity and continuity:

- **Project Charter / One-pager** — Problem statement, goals, success metrics, and stakeholders
- **Roadmap & Release Plan** — High-level milestones and delivery timeline
- **Sprint/Iteration Backlog** — Prioritized work items with acceptance criteria
- **Definition of Done (DoD)** — Shared understanding of what "complete" means
- **Risk Register** — Tracked risks with impact, likelihood, and mitigation plans
- **Retrospective Notes** — Learnings and action items from sprints and releases

### Communication Cadence

Consistent communication rhythms keep stakeholders aligned:

- **Daily Standups** (15 min) — Team sync on progress, blockers, and dependencies
- **Weekly PM + PdM Sync** — Alignment on priorities, metrics, and risks
- **Twice-Weekly Team Standups** — Delivery team progress and coordination
- **Monthly Stakeholder Updates** — High-level status for sponsors and stakeholders
- **Ad-hoc Escalations** — When blockers or decisions cannot wait for regular syncs

### For Retrospectives
1. Schedule a retrospective using **[Retrospective & Continuous Improvement](./octoacme-retrospective-and-continuous-improvement.md)**
2. Capture learnings and add action items to your backlog
